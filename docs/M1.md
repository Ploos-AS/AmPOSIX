# M1 — Portability scanner foundation

M1 turns the M0 design contract into executable AmPOSIX tooling.

## Language policy

AmPOSIX itself is implemented in **C wherever practical**. Core libraries, SDK components and user-facing tools must not require Python or another large scripting runtime. Host-side CI may use standard platform utilities, but the project should remain buildable with a conventional C toolchain and move toward Amiga-hosted operation.

## Implemented

- dependency-free C implementation of `amposix scan`;
- compile-time C feature database;
- native/header/library/adapt/unsupported/investigate model;
- recursive C/C++ source-tree scanning;
- findings reported as `file:line`;
- directory traversal kept separate enough to replace with an AmigaOS backend later;
- C tests and Makefile/CI build.

Example:

```text
tests/fixtures/sample.c:9: adapt         fork               [process] - Prefer spawn-style adaptation; do not fake Unix fork semantics.
tests/fixtures/nested/net.c:4: native        socket             [network]
```

## Design rule

A successful compile is not sufficient evidence of compatibility. Each feature describes the semantic strategy expected on AmigaOS. Entries marked `investigate` must not be promoted until behaviour is understood and testable.

## Next M1 slices

1. header/include detection;
2. machine-readable JSON output generated by C;
3. improve lexical scanning to ignore comments and string literals;
4. database consistency tests;
5. initial public compatibility headers under `include/amposix/`;
6. first compatibility functions;
7. m68k cross-toolchain smoke build;
8. emulator qualification hooks.

## Portability note

The current traversal backend uses the common `dirent/stat` interface for host development. Scanner logic is not to depend on Unix process semantics. Before Amiga-hosted qualification, traversal will be abstracted behind a tiny platform interface and supplied with an AmigaDOS implementation.

## Definition of done

M1 is complete when a small upstream-style C project can be scanned, receive a useful compatibility report, build against the initial SDK where appropriate, and pass automated host/cross validation without proprietary Amiga files in the repository.
