# M1 — Portability scanner foundation

M1 turns the M0 design contract into the first executable AmPOSIX tooling.

## Implemented in the first M1 slice

- machine-readable feature database in `data/features.json`;
- host-side `amposix scan` prototype;
- classification into native/header/library/adapt/unsupported/investigate;
- source-tree scanning for C and C++ files;
- tests covering detection and identifier boundaries;
- a fixture containing both easy and deliberately difficult POSIX calls.

## Design rule

A successful compile is not sufficient evidence of compatibility. Each feature entry describes the semantic strategy expected on AmigaOS.

The database is intentionally conservative. Entries marked `investigate` must not be promoted until the behaviour is understood and testable.

## Next M1 slices

1. JSON output from the scanner for CI and tooling.
2. Header/include detection in addition to function-call detection.
3. Per-file/per-line findings.
4. Feature database validation.
5. Initial public compatibility headers under `include/amposix/`.
6. First host-buildable compatibility functions.
7. Cross-toolchain smoke build.
8. Emulator qualification hooks through the Amiga runtime infrastructure.

## Definition of done

M1 is complete when a small upstream-style C project can be scanned, receive a useful compatibility report, build against the initial SDK where appropriate, and pass automated host/cross validation without proprietary Amiga files in the repository.
